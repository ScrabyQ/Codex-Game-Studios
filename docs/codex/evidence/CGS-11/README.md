# CGS-11 design workflow evidence

The six source-bound overlays cover `brainstorm`, `map-systems`, `design-system`, `quick-design`, `review-all-gdds`, and `propagate-design-change`. `traceability.json` records the six source/target hashes, overlay hashes, thirteen resource mappings, and the observed scope for each. The guarded generator check and a direct byte comparison passed for all 19 generated files. Generated content is not proof of complete behavioral coverage.

The native minimal case in `native-minimal.json` passed its assertions: an actual Codex CLI turn read the installed skill, presented concept choices, used scripted fixture approval, and wrote a substantive `design/game-brief.md` as its only changed file. It created no full concept GDD. The bootstrap and rule-selector shell calls could not start; the run reported those steps **PENDING** and used the documented defaults, which matched the fixture. This does not prove native bootstrap execution.

The native standard case in `native-standard.json` **FAILed its requested assertions**: the CLI returned 0 but shell processes failed to start with `CreateProcessWithLogonW failed: 2`; no fixture files changed, and the agent reported its work **PENDING**. Do not interpret the CLI exit code as a successful design or review.

The retry in `native-standard-retry.json` also **FAILed**: it created the requested index and GDD, but no successful read of the `map-systems` instructions was observed. It also incorrectly reported that pillars and the registry were absent despite their presence in the fixture, and marked progress reviewed/approved while independent review was not assessed. The `map-systems`, `design-system`, and `review-all-gdds` overlays were tightened after this observation to distinguish unknown inputs from verified absence and to prevent unsupported progress claims. The original failures are retained; a patch is not proof the behavior is fixed.

The subsequent `native-context.json` no-write check also **FAILed** its context-read assertions because the native workspace command runner could not launch. The response did report both pillars and registry as **UNKNOWN**, stopped with **PENDING**, and changed no files (`native-context-safety.json`). Since no successful skill read was observed, this is a safety observation rather than proof that the revised overlay caused the behavior or that normal context review works.

`host-workflow.json` records a separate host in-session exercise in the unique `.scratch/cgs11-host-fe4c7e8b` fixture. The actual configuration helper resolved minimal and standard settings. The in-session two-document review returned **CONCERNS**, citing unmeasured UI readability and unresolved timing; it is not an independent review and does not establish a complete cross-GDD review.

For the authorized one-to-two-part change, the actual registry helper identified `parts.md` as a dependent and an ADR scan found the reference to `repair.md`. Hashes recorded before and after show the dependent GDD, registry and ADR were not overwritten. These initial reference observations were followed by the independent Git fixture described below.

That original snapshot is preserved; the later independent fixture received a separately authorized correction as recorded below.
