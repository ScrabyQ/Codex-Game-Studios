# Hook integration and explicit fallback

CGS preserves the 15 declarations in `.claude/settings.json` and all 18 source hook scripts. The adapter is `scripts/codex/hooks.mjs`; generated Bash backends remain under `.agents/hooks/`. The declaration matrix and exact hashes live in `evidence/CGS-24/parity.json`. Original source files are unchanged.

Native activation is **PENDING**. `.codex/hooks.example.json` is a reviewable optional configuration, not an active registration. After inspecting it, a user may copy it to `.codex/hooks.json` and review/trust the commands through the client's Hooks UI or `/hooks`. Do not overwrite an existing hooks file: merge the reviewed groups. No global settings, trust store, permission profiles, Git hooks, or `core.hooksPath` are changed by this integration. Existing host permissions remain the boundary.

The [official hook reference](https://learn.chatgpt.com/docs/hooks), consulted 2026-11-05, documents the seven registered events, `commandWindows`, and `tool_input.command` for Bash and apply_patch. Unified exec is matched as Bash. The example resolves its adapter by walking upward from the session directory, so paths containing spaces and subdirectory invocation work. Each event is synchronous here; a completed Stop archive is preferable to an unverified asynchronous teardown. Backend commands receive `CGS_PROJECT_DIR`, a selected project cwd, and normalized stdin JSON. No invented Codex project-root variable is required.

Run the deterministic adapter without native activation:

```powershell
node scripts/codex/hooks.mjs PreToolUse --root . --input proposal.json
node scripts/codex/hooks.mjs PostToolUse --root . --input written.json
node scripts/codex/hooks.mjs SessionStart --root . --input session.json
node scripts/codex/hook-tests.mjs
```

JSON can instead arrive on stdin. A shell proposal uses `{"tool_name":"Bash","tool_input":{"command":"git status --short"}}`; `cmd` is accepted for direct exec_command payloads. A patch uses `{"tool_name":"apply_patch","tool_input":{"command":"*** Begin Patch\n...\n*** End Patch"}}`; freeform string `tool_input` is also accepted. Legacy explicit Read/Write/Edit payloads retain `file_path`, `content`, `old_string`, `new_string`, `replace_all`, `offset`, and `limit`. Unknown critical tool names, absent shell commands, malformed patches, and ambiguous update contexts return exit 2. Update patches need unique context to reconstruct proposed bytes; use more context or a precise explicit edit when reconstruction is refused.

For an authorized shell action, `node scripts/codex/hooks.mjs run --root . --input proposal.json` checks that exact command and only then invokes Git Bash (or PowerShell for `tool_name: PowerShell`). It never executes denied input. It runs in the selected root; use explicit `--root` when needed. A zero check result is not user approval and does not grant permissions. File actions remain the caller's responsibility: check first, execute only on exit 0, then invoke PostToolUse with the same affected paths. A postwrite error describes a file already written; it cannot undo or prevent that write. CI can run the fixture suite; wiring the suite into repository CI belongs to CGS-28.

Requirements are Node, Git, and Bash; Windows defaults to `C:\Program Files\Git\bin\bash.exe`, with `CGS_BASH` for another installed executable. Bash backends also use ordinary Git Bash utilities and Python for shared configuration and staged-JSON checks. Missing essential backend files or a failed backend process returns exit 2 with a reason, never a clean result. The Windows host initially blocked Bash startup (3221225794); the same tests passed through the already authorized host execution path. That is host execution evidence, not proof that a nested Codex child can launch those commands. Linux backend execution subsequently passed in [actual CI](https://github.com/ScrabyQ/Codex-Game-Studios/actions/runs/42043549446); native activation remains PENDING.

The complete command `git remote set-url --push upstream DISABLED` is safe remote configuration, not a push. Its exact quoted-argument variants are recognized by the adapter. Extra commands or a different destination retain normal push inspection. The [clean-install regression](evidence/CGS-30/hook-fix.md) records the initial false positive and the tested correction.

PreToolUse protects explicit `.env*` paths, `.uasset`/`.umap` paths, force pushes, destructive Git operations, recursive forced deletion, privilege escalation patterns, and pushes naming the upstream or its Donchitos URL. It also checks configured upstream destinations for ordinary Git push forms. Every file and move destination in a patch is inspected before reading proposed content. JSON syntax is checked in proposed writes and reconstructed patches. The upstream registry and write guard still produce advisory warnings with exit 0; their warnings must not be described as enforced prohibitions. The commit backend checks staged data JSON. PostToolUse validates the actual asset data bytes, then runs naming and skill-change advisories.

This detector is deliberately finite, not a universal shell parser. Dynamic aliases, encoded programs, indirect script effects, interactive `write_stdin`, specialized tools outside the hook path, and arbitrary shell-produced file writes cannot be completely inferred. Explicit critical MCP/file tool names that lack a mapping are refused with an actionable message. Shell-produced file changes need explicit PostToolUse paths or the normal validation workflow. Conservative false positives include commands mentioning protected paths and ambiguous patches; simple quoted display-only commands are accepted. Host permissions and review remain necessary even when native hooks are trusted. Native hook timeout/startup failures may fail open in the client; only a completed explicit CLI exit-2 check establishes a denial in the fallback path.

Lifecycle fallback uses the same event CLI with a JSON object containing `session_id` and, where applicable, `agent_type`, `agent_id`, or `source`. SessionStart previews the persisted checkpoint and reports gaps; PreCompact records compaction; Stop archives state and reports spawn counts. These are observations, not phase verdicts. For a delegated return contract, call SubagentStop with `expected_artifact` copied from the actual assignment. It reports presence/missing status and requires content review. Codex transcript structure is unstable, so the original Claude transcript parser is preserved but not used as an asserted native contract extractor; without `expected_artifact`, the adapter explicitly reports PENDING. An in-session role review is not an independent subagent.

There is no documented Notification event in this integration. `node scripts/codex/hooks.mjs Notification --root . --input status.json` prints a manual status from `{"message":"Review needed"}`. It neither synthesizes an approval event nor claims an automatic Windows toast. The original notify script is retained for provenance. `log-instructions.sh` was not one of the 15 declarations and is not registered as a fictional InstructionsLoaded event. Rule-selection evidence comes from the explicit selector. `update-check.sh` remains a helper; no background upstream update job is installed.
